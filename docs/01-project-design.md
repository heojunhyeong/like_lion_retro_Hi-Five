# 개발 계획서

## 1. 프로젝트 개요
다양한 게임 혹은 취미생활을 같이 즐길 사람들을 찾는 매칭 커뮤니티입니다. 사용자가 매칭방을 생성하고, 조건에 맞는 참가자를 승인하거나 거절하며 실시간으로 소통할 수 있는 환경을 제공합니다.

## 2. 기술 스택

| 구분 | 기술 스택 |
| :--- | :--- |
| 백엔드 | Spring Boot |
| 프론트엔드 | React |
| 데이터베이스 | MySQL |
| 컨테이너 | Docker, Docker Compose |
| 배포 | AWS EC2 |
| 실시간 통신 | WebSocket (STOMP), SSE (Server-Sent Events) |
| 보안 | Spring Security, JWT |

## 3. 전체 흐름

### 3.1 계정 및 인증 흐름
사용자가 회원가입을 하면 사용자 정보가 MySQL에 저장됩니다. 로그인 시 서버는 사용자의 신원을 확인하고 Access Token과 Refresh Token을 발급합니다.

이후 사용자의 모든 요청은 JWT 필터를 거쳐 인증되며, 로그아웃 시 서버의 리프레시 토큰을 무효화하여 보안을 유지합니다.

비밀번호를 분실한 경우 이메일 인증 토큰을 통해 재설정 프로세스가 진행됩니다.

### 3.2 매칭방 생성 및 조회 흐름
인증된 사용자는 제목, 카테고리, 인원 제한, 입장 방식(즉시 입장/승인제) 등의 조건을 설정하여 매칭방을 생성할 수 있습니다.

다른 사용자는 카테고리별 검색이나 키워드 검색을 통해 생성된 매칭방 목록을 조회하고, 상세 정보를 확인할 수 있습니다.

### 3.3 매칭 신청 및 승인 관리 흐름
사용자가 특정 매칭방에 참여 신청을 하면, 해당 정보가 참가자 목록에 추가됩니다.

입장 방식이 승인제인 경우, 방장은 실시간 알림(SSE)을 통해 신청 내역을 확인합니다. 방장은 참가자 목록 조회 API를 통해 대기 중인 인원의 정보를 확인한 후, 승인 혹은 거절 API를 호출하여 참여 여부를 결정합니다. 승인된 사용자는 해당 방의 정식 멤버로 전환됩니다.

### 3.4 실시간 소통 및 알림 흐름
매칭과 관련된 중요한 이벤트(신청, 승인 등)는 SSE를 통해 사용자에게 즉시 알림으로 전달됩니다.

매칭에 성공하여 방에 입장한 사용자들은 STOMP 기반의 웹소켓 채널을 통해 해당 매칭방의 다른 멤버들과 실시간으로 채팅을 주고받을 수 있습니다.

### 3.5 퇴장 및 종료 흐름
사용자는 참여 중인 매칭방에서 언제든지 퇴장할 수 있습니다.

일반 참가자가 퇴장하면 참여 인원수가 조정되며, 방장이 퇴장하는 경우에는 해당 매칭방이 삭제되고 관련 데이터가 정리됩니다.
